## Why

BrewForm tracks recipes, but not what happens when users actually brew them. There is no way to
record "I brewed this recipe on Tuesday, used 16g instead of 15g, and it was too bitter" — the
feedback loop that makes a recipe collection useful over time. F02 (brew journal) closes that gap:
users log each brew event with actual measurements, deviations, notes, and a 1–10 personal rating,
and get back per-recipe brew history plus aggregate stats. It is also the named prerequisite for
F03 (profile stats), F20, F25's offline brew-log sync, and F28's guided-brew completion hook
(`plans/ROADMAP.md:34`).

## What Changes

- **New Drizzle table** `brew_log` in `packages/db/src/schema.ts`: soft-deletable (`createdAt` /
  `updatedAt` / `deletedAt`), FKs to `users`, `recipes`, and (nullable) `recipeVersions`, `real()`
  columns for actual yield/dose, `text` notes, integer `personalRating` with a 1–10 CHECK (parity
  with the D21 rating scale), positive-value CHECKs on the actuals. Composite indexes
  `(userId, brewedAt)` and `(recipeId, brewedAt)` (D23 convention) plus `deletedAt`. Relations
  added to `usersRelations`, `recipesRelations`, `recipeVersionsRelations`, plus a new
  `brewLogsRelations` block. Migration auto-generated via `make db-generate`.
- **New shared Zod input schemas** in `packages/shared/src/schemas/brew-log.ts`:
  `BrewLogCreateSchema`, `BrewLogUpdateSchema` (at-least-one-field refine, nullable fields for
  clearing values). Re-exported from the schemas barrel.
- **New response Output Schemas** in `packages/shared/src/schemas/responses/brew-log.ts`:
  `BrewLogOutputSchema`, `BrewLogListItemOutputSchema` (extends with joined recipe title/slug),
  `UserBrewStatsOutputSchema`, `RecipeBrewStatsOutputSchema` (`brewCount` / `avgBrewRating` —
  named distinctly from the community `avgRating` on `RecipeDetailOutputSchema`, which is a
  different metric). Re-exported from both barrels.
- **New API module** `apps/api/src/modules/brew-log/` following the 3-layer pattern: `model.ts`
  (pure Drizzle data-access, `isNull(deletedAt)` everywhere) → `service.ts` (ownership checks,
  recipe/version existence validation, structured logging, string-error throws) → `index.ts`
  (7 Hono routes, each with `describeRoute()` OpenAPI metadata, `zValidator`, `zodValidationHook`).
- **Route registration** in `apps/api/src/routes/index.ts`: `routes.route('/api/v1/brew-logs', brewLog)`.
- **New `Brew Logs` OpenAPI tag** registered in `apps/api/src/routes/openapi.ts`; `/api/v1/brew-logs`
  added to `IN_SCOPE_BASE_PATHS` in `openapi.coverage.test.ts`.
- **Privacy model**: individual brew logs are strictly owner-private (all log read/write routes
  require auth and filter by `userId`). Only aggregate recipe stats (`brewCount`,
  `avgBrewRating`) are public via the optional-auth stats route.
- **Frontend**: two new pages (`BrewLogListPage` at `/brew-logs`, `BrewLogFormPage` at
  `/brew-logs/new` and `/brew-logs/:id/edit`), four new components (`BrewLogForm`, `BrewLogCard`,
  `BrewHistorySection`, `RecipeBrewStats` — the "Brew Again" affordance is the
  `BrewHistorySection` header button, no separate component), a typed `brewLogApi` in
  `apps/web/src/api/index.ts`, new routes in `router.tsx` with loaders, a brew-history tab on
  `UserProfilePage` (own profile only), and brew stats + history section on `RecipeDetailPage`.
- **i18n**: new `brewLog.*` keys in both `en.json` and `tr.json` (parity enforced by test).
- **Tests**: DB schema index/column/constraint assertions, shared schema unit tests, API
  model/service/route integration tests (real PostgreSQL, `createTestApp` pattern), and frontend
  page/component tests.
- **Seed**: idempotent `seedBrewLogs` helper in `seed.ts` for dev data.

## Capabilities

### New Capabilities

- `brew-journal`: Log brew events per recipe with actual measurements, notes, and a 1–10 personal
  rating. Owner-only CRUD with soft delete. Per-user and per-recipe paginated brew history.
  Aggregate stats: user-level (total brews, recent frequency) and recipe-level (times brewed,
  average personal rating — public). "Brew Again" flow pre-filling the log form from a recipe's
  current version.

### Modified Capabilities

- `db-indexes`: New composite indexes for the `brew_log` table — `brew_log_user_brewed_idx` on
  `(userId, brewedAt)` and `brew_log_recipe_brewed_idx` on `(recipeId, brewedAt)` — covering the
  two list query patterns (user history, per-recipe history), plus `brew_log_deleted_at_idx`.

## Impact

- **Database**: New migration `0014_<codename>.sql` auto-generated by `make db-generate`
  (`CREATE TABLE "brew_log"` + 3 indexes + 3 CHECK constraints + FKs). Applied via
  `make db-migrate`. No manual SQL.
- **Shared schemas**: New `brew-log.ts` input-schema file + `responses/brew-log.ts` output-schema
  file. Both barrels gain explicit export blocks. No existing schema changes.
- **API**: New self-contained module — no changes to existing modules except `routes/index.ts`
  (one import + one `routes.route(...)` line) and `routes/openapi.ts` (one tag entry).
  `usersRelations`, `recipesRelations`, `recipeVersionsRelations` in `packages/db/src/schema.ts`
  each gain one `many(brewLogs)` line (additive).
- **Frontend**: New pages/components are additive. `router.tsx` gains three routes.
  `UserProfilePage.tsx` gains a `brews` tab (own-profile only). `RecipeDetailPage.tsx` gains a
  stats row + brew-history section in the main column. `api/index.ts` gains a `brewLogApi` object.
  `en.json`/`tr.json` gain `brewLog.*` keys.
- **OpenAPI**: New `Brew Logs` tag; 7 new documented routes. Coverage test updated.
- **Tests**: New test files across `packages/db`, `packages/shared`, `apps/api`, `apps/web`.
  Existing tests unaffected.
- **No third-party dependencies** — uses existing Drizzle, Hono, Zod, react-router. No chart
  library (stats are plain numbers).
- **Out of scope**: F28 guided-brew completion hook (F28 is unimplemented; it will POST to this
  change's create endpoint when it lands), public sharing of brew logs (F26 may add a visibility
  flag later), time-series charts.
