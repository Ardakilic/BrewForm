# DB Indexes (Delta)

Add a new composite index `recipe_created_at_id_idx` on `(createdAt DESC, id)` to support
cursor-based pagination queries on the recipes table.

## ADDED Requirements

### Requirement: Composite index for cursor pagination on recipes

The system SHALL have a composite B-tree index named `recipe_created_at_id_idx` on
`recipes(createdAt DESC, id)` to support cursor-based queries. The index is added by editing
the Drizzle schema TypeScript file (`packages/db/src/schema.ts`) — the SQL migration is
auto-generated by `make db-generate`. **No SQL migration files are manually edited.**

The resulting query that the index supports:

```sql
SELECT * FROM recipe
WHERE deleted_at IS NULL
  AND (created_at, id) < ($cursorCreatedAt, $cursorId)
ORDER BY created_at DESC, id DESC
LIMIT $perPage + 1;
```

The Drizzle schema SHALL define this index as:

```typescript
index('recipe_created_at_id_idx')
  .on(table.createdAt.desc(), table.id.desc()),
```

This is the codebase's first use of `.desc()` in an index definition — Drizzle v0.31.0+ supports
column-specific ordering via `.asc()` / `.desc()` in PostgreSQL index definitions.

The index docblock SHALL state:

```
Cursor-based pagination: supports (createdAt DESC, id) < (cursor) queries.
Both columns are DESC because the most common query is "newest first" feed.
Postgres can scan this index backward for ASC queries.
```

#### Scenario: Index exists after migration

- **WHEN** `make db-generate && make db-migrate` is executed
- **THEN** `\di recipe_created_at_id_idx` in psql shows the index on `recipes(createdAt DESC, id)`

#### Scenario: Index is verified by schema test

- **WHEN** `make test` runs
- **THEN** the `packages/db/src/schema-indexes.test.ts` test verifies `recipe_created_at_id_idx`
  exists with columns `[createdAt, id]` and is not unique

#### Scenario: Index is used by cursor query

- **WHEN** `EXPLAIN ANALYZE` is run on the cursor pagination query
- **THEN** the query plan shows an Index Scan or Index Only Scan using `recipe_created_at_id_idx`
  (not a Sequential Scan)

---

## MODIFIED Requirements

### Requirement: All query-critical composite indexes exist on recipes table

The recipes table SHALL have the following composite indexes:
- `recipe_author_visibility_idx` on `(authorId, visibility)` — author-scoped lists
- `recipe_visibility_created_idx` on `(visibility, createdAt)` — public feed sorted by date
- `recipe_visibility_like_count_idx` on `(visibility, likeCount)` — trending queries
- `recipe_created_at_id_idx` on `(createdAt DESC, id)` — cursor-based pagination (**NEW**)

Every new index MUST have a JSDoc comment documenting the query pattern served, column ordering
rationale, and nullable column handling.

The schema-level verification test at `packages/db/src/schema-indexes.test.ts` SHALL use
`getTableConfig` from `drizzle-orm/pg-core` to introspect indexes and assert names, columns,
and uniqueness. The test SHALL include a new assertion for `recipe_created_at_id_idx` alongside
the existing 17 index assertions.

#### Scenario: All indexes verified including the new one

- **WHEN** the index verification test runs
- **THEN** all indexes are asserted including the new `recipe_created_at_id_idx`
- **AND** the test asserts columns `[createdAt, id]` and `unique: false`
